# Express server project using @themost framework

A starter project for building data-driven web applications with [Express](https://expressjs.com/) and the [MOST Web Framework](https://github.com/themost-framework/).

It comes with:

- an Express 5 application wired with [`@themost/express`](https://github.com/themost-framework/express), which registers a data context on every request
- a set of schema.org-based data models (`Thing`, `Account`, `User`, `Group`, `Workspace`, `Action`, `Permission` etc.)
- a sample router for serving users (`/v1/users`)
- a SQLite database adapter (`@themost/sqlite`) for local development
- server-side rendering with [Twig](https://github.com/twigjs/twig.js) views
- ES module syntax and decorators, compiled with [Babel](https://babeljs.io/)
- [`@themost/cli`](https://github.com/themost-framework/cli) for generating models, classes, listeners and controllers

## Getting started

Create a new project with the `themost` command line utility:

    npx @themost/cli new project my-app --template express
    cd my-app
    npm install

Build and start the application:

    npm run build
    npm start

The application server listens on `http://localhost:3000` by default. Use `--port` (`-p`) and `--host` (`-h`) to change it:

    node dist/server/standalone.js --port 8080 --host 0.0.0.0

## Scripts

| Script          | Description                                                                 |
|-----------------|-----------------------------------------------------------------------------|
| `npm run build` | Compiles `server/` into `dist/server/` with Babel (copies JSON, views etc.) |
| `npm start`     | Starts the compiled application (`dist/server/standalone.js`)               |
| `npm run dev`   | Starts the application with `nodemon`, rebuilding on every change in `server/` |
| `npm run cli`   | Runs the `themost` command line utility                                     |

## Configuration

Application settings live in `server/config/app.json`. By default the project uses a SQLite database stored at `db/local.db`:

```json
"adapters": [
    {
        "name": "development",
        "invariantName": "sqlite",
        "default": true,
        "options": {
            "database": "db/local.db"
        }
    }
]
```

To use another database, install the corresponding adapter (e.g. `@themost/pg`, `@themost/mysql`, `@themost/mssql`), register it under `adapterTypes` and add a new entry under `adapters`.

> **Important:** replace `settings.crypto.key` and `settings.auth.unattendedExecutionAccount` with your own random values before deploying. You can generate one with `npx themost random hex --length 48`.

## Data models

Data models are defined as JSON files in `server/config/models/`. Each model describes its fields, relations, privileges and event listeners, and may inherit from another model (e.g. `User` inherits `Account`, which inherits `Thing`). The database schema is created or upgraded automatically the first time a model is used.

A model may also have a class in `server/models/` that extends `DataObject` and adds custom behavior. For example, `User` exposes a `Me` function which returns the interactive user:

```js
@EdmMapping.entityType('User')
class User extends Account {
    @EdmMapping.func('Me', 'User')
    static async getMe(context) {
        return await context.model('User').where('name').equal(context.user && context.user.name).getTypedItem();
    }
}
```

Event listeners in `server/listeners/` hook into data operations (`beforeSave`, `afterSave`, `beforeRemove` etc.). `SetUserCredentials` is an example which stores user credentials after a new user is inserted.

### Enumerations

`Enumeration` (schema.org [Enumeration](https://schema.org/Enumeration)) is the base model for lists of predefined values such as statuses, types or categories. It has no fields of its own; every enumeration gets `id`, `name`, `alternateName`, `description` and `url` from `Thing`.

`ActionStatusType` is an example. It *implements* `Enumeration`, which means it gets the same fields but stores its values in a separate table, defines a unique constraint on `alternateName` and seeds the four schema.org action statuses:

```json
{
    "name": "ActionStatusType",
    "implements": "Enumeration",
    "constraints": [
        { "type": "unique", "fields": [ "alternateName" ] }
    ],
    "seed": [
        { "name": "PotentialActionStatus", "alternateName": "PotentialActionStatus" },
        { "name": "FailedActionStatus", "alternateName": "FailedActionStatus" },
        { "name": "CompletedActionStatus", "alternateName": "CompletedActionStatus" },
        { "name": "ActiveActionStatus", "alternateName": "ActiveActionStatus" }
    ]
}
```

Seed items are inserted when the model's table is created. Other models refer to an enumeration with a field of that type. `Action.actionStatus`, for example, is an `ActionStatusType` that defaults to `PotentialActionStatus`:

```json
{
    "name": "actionStatus",
    "type": "ActionStatusType",
    "value": {
        "$value": { "alternateName": "PotentialActionStatus" }
    }
}
```

Because `alternateName` is unique, you can use it to refer to an enumeration value instead of its `id`, both when you save and when you query:

```js
// set an action status by its alternate name
await context.model('Action').save({
    id: action.id,
    actionStatus: { alternateName: 'CompletedActionStatus' }
});

// find completed actions
const items = await context.model('Action')
    .where('actionStatus/alternateName').equal('CompletedActionStatus')
    .select('id', 'name', 'actionStatus/alternateName as status')
    .getItems();
```

To add your own enumeration, create a model which implements `Enumeration`, add a unique constraint on `alternateName` and list its values under `seed`.

### Using models inside routes

The `setContext()` middleware registers a data context on every request as `req.context`:

```js
router.get('/groups', async (req, res, next) => {
    try {
        const items = await req.context.model('Group')
            .where('name').startsWith('Admin')
            .orderBy('name')
            .take(25)
            .getItems();
        return res.json(items);
    } catch (err) {
        return next(err);
    }
});
```

### Users router

`server/routes/users.js` is a sample router which serves the `User` model with plain `@themost/data` queries. It is mounted at `/v1/users` in `server/app.js`:

```js
import {usersRouter} from './routes/users';

app.use('/v1/users', usersRouter());
```

| Method   | Path              | Description                                                                 |
|----------|-------------------|-----------------------------------------------------------------------------|
| `GET`    | `/v1/users`       | Returns a page of users as `{ total, skip, value }` (25 items unless `$top` is set) |
| `GET`    | `/v1/users/me`    | Returns the interactive user, including the groups they belong to           |
| `GET`    | `/v1/users/:id`   | Returns a user by identifier, including groups, or `404`                    |
| `POST`   | `/v1/users`       | Inserts a new user (any `id` in the body is ignored) and returns `201`      |
| `PUT`    | `/v1/users/:id`   | Updates an existing user, or returns `404`                                  |
| `DELETE` | `/v1/users/:id`   | Removes an existing user and returns `204`, or `404`                        |

The list endpoint passes the request query to `DataModel.filterAsync()`, so it accepts `$filter`, `$select`, `$orderby`, `$expand`, `$top` and `$skip`:

    GET /v1/users?$filter=enabled eq true&$select=id,name&$orderby=name&$top=10

Every query runs through `req.context`, so the privileges defined in `User.json` apply to these routes as well. Use the router as a template for serving other models.

## Authentication

`server/routes/auth.js` contains an example router which uses [Passport](https://www.passportjs.org/) with a local strategy that validates users against the `User` and `UserCredential` models. It is not mounted by default. To enable it, add session support (e.g. `express-session`) and register the router in `server/app.js` before the other routes:

```js
import passport from 'passport';
import authRouter from './routes/auth';

app.use('/', authRouter(passport));
```

and add a `login` view in `server/views/`.

## Using the CLI

`@themost/cli` is installed as a dev dependency and reads `.themost-cli.json` to locate the project sources (`server`) and the compiled output (`dist/server`).

    npm run cli -- generate model Article         # new model definition in server/config/models
    npm run cli -- generate class Article         # new model class in server/models
    npm run cli -- generate listener OnArticleSave  # new listener in server/listeners
    npm run cli -- modeler ls                     # list data models
    npm run cli -- modeler extract Article        # extract a schema.org model and its dependencies
    npm run cli -- cat User --filter "enabled eq true" --top 10
    npm run cli -- import data/groups.json --model Group

Run `npm run cli -- --help` for the full list of commands.
