# Working with the Modeler

```
themost modeler <command>
```

The modeler works on a catalog of definitions bundled with the CLI: the schema.org JSON-LD vocabulary (`modeler/schemas/schema.jsonld`) plus `xmlschema.jsonld` and `themost.jsonld`, which are appended to it at load time. It turns an RDFS class into a MOST data model definition.

| Command | Reads project config | Description |
|---------|----------------------|-------------|
| `modeler ls [model]` | no | Lists the available models |
| `modeler inspect <model>` | no | Prints a model and its fields |
| `modeler info <model>` | no | Deprecated alias of `inspect` |
| `modeler extract <model>` | yes | Writes the model and its dependencies to the project |

## modeler ls

```
themost modeler ls [model]
```

`model` is an optional positional argument. It is used as a case-insensitive regular expression (for example `^Person`); a value which is not a valid regular expression is matched as plain text. It is tested against each class name and against the name of its parent class (`subClassOf`). Output is a table with the columns `name`, `description` (truncated to 32 characters) and, when present, `subClassOf`. If nothing matches it logs `There are no models matching "<model>".`.

```sh
themost modeler ls
themost modeler ls ^Action
```

## modeler inspect

```
themost modeler inspect <model>
```

Prints a `Properties` section (`name`, `description` truncated to 80 characters, `inherits`, `implements`) followed by a `Fields` section with the columns `name`, `description` (32 characters), `type` and `from`. `from` shows the parent model of fields which come from an implemented or inherited model (the chain is followed recursively). If the name is not a valid class, it logs `The specified model cannot be found.`.

```sh
themost modeler inspect UpdateAction
```

`info` has the same arguments and behavior and its description says it is deprecated.

## modeler extract

```
themost modeler extract <model> [options]
```

`model` is positional and required. The command has no options of its own besides the global ones.

Steps:

1. It extracts the definition of the model and, recursively, every model referenced by its `inherits`, `implements` and field types (only schema.org classes, not data types such as `Text` or `Number`).
2. It does the same for `User` and `Permission`, which are always extracted together with the requested model.
3. A definition is skipped when `<base>/config/models/<name>.json` already exists and does not contain `"@modeler.generated": true`. Files which were generated by the CLI are overwritten, so manual edits are lost unless you remove that property.
4. Remaining definitions go through the post formatters (see below) using a live application context, and are written to `<base>/config/models/<name>.json` with 4 space indentation.

If the requested model is not found, or if it is skipped because a hand-written definition exists, the command fails with `Model "<name>" could not be found or it already exists and has not been generated by @themost/cli` and a non-zero exit code.

```sh
themost modeler extract Article
```

Expected result: `Article.json` and the definitions it depends on (for example `CreativeWork`, `Thing`, `Person`) appear in `server/config/models`, and each prints `Model "<name>" has been successfully created.`. The application is created from `<out>/config`, so the project must have been built first.


### Generated definition

Each definition has `@id`, `name`, `description`, `title`, `abstract`, `sealed`, `hidden`, `version` (`1.0.0`), `inherits`, `implements`, `@modeler.generated`, `@modeler.help`, `fields` and `privileges` (mask 15 for everyone and for `Administrators`). Properties whose value is `null` are removed. Enumeration members of schema.org enumerations become `seed` items.

### Formatters

Definitions are adjusted by formatters in `modeler/formatters.js` while they are built:

- `Thing` becomes abstract and hidden, gets a primary `id` field of type `Counter`, loses `potentialAction`, and `identifier` and `image` become `Text`.
- `Intangible` and `Enumeration` become abstract and hidden.
- `Person` and `Organization` inherit `Party`.
- Models inheriting `Enumeration` or `Intangible` implement it instead (enumeration ids become `Integer`).
- `StructuredValue` implements `Intangible`, is hidden and has an `Integer` id; models inheriting it are hidden.
- A plural field is dropped when its singular form also exists on the model (`trimPluralizedPropertyFormatter`).

### Post formatters

`modeler/postFormatters.js` runs on the final definitions with access to the other models. `formatJsonTypedAttribute` marks the models `StructuredValue`, `Quantity` and `Rating` and models inheriting from them as hidden, and changes fields typed with such a model to type `Json`, storing the original type in `additionalType`.

## Summary

Use `modeler ls` and `modeler inspect` to browse the catalog and `modeler extract` to materialize a model in `server/config/models`. Remove `@modeler.generated` from a file before editing it by hand, otherwise a later extraction will overwrite it. Next, create classes with Generating Components.
